# ユースケース

adhd-report は、ADHD の読み手向けに Claude Code の出力を整えるスキルです。
元の [i-have-adhd](https://github.com/ayghri/i-have-adhd)（MIT、Ayoub Ghriss）を土台に、
利用者自身の過去ログから見えた読みにくさの原因に合わせた決まりを足しています。

## 利用者と場面

利用者は ADHD の特性を持つ開発者です。画面に出ていない情報は保持できません。
別の話に移ると、直前の文脈も外れます。

| 場面 | 例 |
|---|---|
| S1 単独のセッション | 1つのリポジトリで Claude Code と作業する |
| S2 複数エージェントをまとめて報告するセッション | 司令塔のセッションが、複数のエージェントの完了や停止の通知を受けて報告する |

## UC1 判断を1件ずつ聞かれる

- 場面: S1・S2
- 流れ: 判断が複数ある時、Claude が「N件あります」と1行で言い、1件目だけを出す。答えをもらってから次を出す
- 成功条件: 利用者が、一覧から1件ずつ聞き返す往復をしなくて済む

## UC2 判断の依頼が、その1回の返事だけで分かる

- 場面: S1・S2
- 流れ: Claude が判断を聞く時、どのタスクか、何を決めるか、なぜ今か、各案の中身、おすすめを毎回書く。画面の別の場所に出る質問（AskUserQuestion）でも同じにする
- 成功条件: 利用者が、スクロールバックして過去の問い合わせを探さずに答えられる

## UC3 分かりにくい文を、流れに言い換えてもらう

- 場面: S1・S2
- 流れ: 名詞が連なる圧縮文を避け、「誰が・何を・どこへ」の流れで、1文に1つの事だけを書く
- 成功条件: 「意味がよく分からない」という聞き返しが減る

## UC4 「〜という理解で合っていますか」に、はい／いいえで答えてもらう

- 場面: S1・S2
- 流れ: 利用者が理解を言い直して確かめる。Claude は冒頭で「はい」か「いいえ」を言い、根拠を1〜2点続ける
- 成功条件: 追加の質問なしで、次の作業に進める

## UC5 自分の操作が要る時に、すぐ気づく

- 場面: S1・S2
- 流れ: 承認や、フォルダの信頼の確認で止まった時、報告の1行目が「あなたの操作:」になり、番号付きの手順が続く
- 成功条件: 操作が必要だと、1行目で分かる
- 範囲外: ターミナルのタブ名を変えるなどの画面の表示。スキルの外で扱う

## UC6 内容が変わらない通知に、短く返される

- 場面: S2
- 流れ: 報告済みと同じ完了通知、監視の期限切れ、起動時の既存の完了行が届く。Claude は記録の更新だけをして、括弧書きの1行で返す。新しい完了は普通に報告する
- 成功条件: 「新しいことはありません」の長い返事が画面を埋めない。完全な無言ではなく、1行は出る（ハーネスが出力を求めるため）

## UC7 全体の状況を、決定待ちから読める

- 場面: S2
- 流れ: 「全体の状況」を聞かれると、決定待ち、作業中、完了の順で、1エージェント1行で返す
- 成功条件: 利用者が状況を打ち直さなくても、返事待ちの件が先頭に見える

## UC8 決定待ちを、話が一段落した時に知らされる

- 場面: S2
- 流れ: 決定待ちが溜まっていれば、会話が一段落した時に知らせる。毎回の報告の末尾には付けない。話の途中では割り込まない。ただし UC5 は、すぐ知らせる
- 成功条件: 決定待ちが流れて消えない

## UC9 台帳の1行が短く保たれる

- 場面: S2（TASKS.md のような台帳を持つ場合）
- 流れ: 台帳の1行を短くし、経緯を書かない
- 成功条件: 台帳の更新の差分が、画面を埋めない

## UC10 常時有効にする

- 場面: S1・S2
- 流れ: `~/.claude/.adhd-report-always` を作ると、セッションの開始時（startup、resume、clear、compact）にルールが自動で入る。「stop adhd-report」で、そのセッションだけ止まる
- 成功条件: 元の plugin と並べて入れても、印のファイルと止める言葉が取り違えられない

## UC11 スキルを改修する（開発者向け）

- 流れ: 決まりを足す時、ドキュメント、テスト（落ちることの確認）、本文の順で変える
- 成功条件: `python3 -m unittest discover -s tests` が通る
